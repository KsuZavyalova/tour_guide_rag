# Мультиязычный голосовой туристический ассистент на базе Wikivoyage

## Краткое описание

Прототип голосового туристического ассистента, принимающего устные запросы на любом из поддерживаемых языков и отвечающего голосом на языке пользователя. Система использует базу знаний English Wikivoyage, retrieval-Augmented Generation (RAG) и поддерживает ведение связного многораундового диалога с учётом истории разговора.

Пользователь может задать вопрос голосом (например, "Расскажи про достопримечательности Рима"), получить ответ текстом и озвученным аудио, а затем продолжить диалог уточняющими вопросами ("А как туда добраться на метро?", "Где можно пообедать рядом?") — система сохраняет контекст и корректно разрешает местоимения и ссылки на предыдущие темы.

## Цель проекта

Создать работающий end-to-end пайплайн мультиязычного голосового ассистента, демонстрирующий возможности современных NLP-моделей в прикладной задаче:
- распознавание речи на множестве языков;
- машинный перевод на общий язык для поиска;
- семантический поиск по структурированной базе знаний;
- генерация связного ответа с опорой на найденные факты;
- синтез речи на языке пользователя;
- ведение диалога с сохранением контекста.

## Архитектура и методы

Пайплайн состоит из семи последовательных этапов:

1. **Парсинг базы знаний.** Извлечение структурированной информации из дампа English Wikivoyage. Разбиение статей на тематические разделы (sights, food, transport, sleep, shopping и др.) с очисткой вики-разметки. Итог: 19 507 статей, 86 326 разделов.

2. **Чанкинг и векторизация.** Разбиение текстовых разделов на чанки с помощью `RecursiveCharacterTextSplitter` (chunk_size=500, chunk_overlap=100). Векторизация эмбеддинг-моделью `sentence-transformers/all-MiniLM-L6-v2`. Построение индекса в ChromaDB (153 762 чанка).

3. **Распознавание речи (ASR).** Модель OpenAI Whisper (`small`) с автоматическим определением языка.

4. **Перевод запроса.** Модели Helsinki-NLP/opus-mt (MarianMT) для перевода с 19 языков на английский. Переводчик загружается по требованию и кэшируется.

5. **Retrieval.** Семантический поиск в ChromaDB по английскому варианту запроса. Для многораундового диалога запрос расширяется последними репликами пользователя, чтобы retrieval учитывал контекст (например, понимал, что "туда" относится к Риму из предыдущего вопроса).

6. **RAG-генерация.** Локальная LLM `Qwen/Qwen2.5-1.5B-Instruct` генерирует ответ на языке пользователя, опираясь только на найденные чанки из Wikivoyage. В промпт передаётся вся история диалога и при необходимости — её суммаризация.

7. **Синтез речи (TTS).** Microsoft Edge TTS с выбором голоса под каждый язык (например, `ru-RU-SvetlanaNeural`, `en-US-JennyNeural`, `de-DE-KatjaNeural`).

## Инструкция по запуску

Проект оформлен в виде единого Jupyter Notebook. Никаких дополнительных действий не требуется: дамп Wikivoyage скачивается автоматически при первом запуске, модели подгружаются из Hugging Face, векторная база строится в ходе выполнения. При повторных запусках notebook подхватывает уже сохранённые артефакты с Google Drive.

## Результаты

Прототип полностью работоспособен и демонстрирует связное поведение на всех этапах пайплайна.

**Работоспособность пайплайна.** Запрос на русском, немецком, французском, испанском, итальянском или английском языках корректно распознаётся, переводится, находится в базе, преобразуется в связный ответ и озвучивается на языке пользователя.

**Многораундовый диалог.** Система сохраняет контекст разговора: после вопроса про Рим уточняющие вопросы "А как туда добраться?" и "Где рядом пообедать?"

## Перспективы улучшения

Прототип имеет ряд направлений для развития:

1. **Более точная модель ASR.** Переход с Whispe `small` (244M) на `medium` (769M) существенно снизит WER и устранит случаи галлюцинаций при распознавании некоторых языков.

2. **Более мощная LLM.** Переход на LLM с большим количеством параметров(можно многоязычную) улучшит качество генерации и снизит вероятность галлюцинаций, особенно на агрегирующих вопросах.

3. **Расширение базы знаний.** Добавление разделов Wikivoyage на других языках (ru, de, fr, es, it) позволит отвечать на вопросы напрямую, без перевода, и повысит покрытие.

4. **Извлечение именованных сущностей (NER).** Предварительное извлечение названий городов, достопримечательностей и адресов из запроса может быть позволит точнее формировать поисковый запрос и фильтровать результаты.

5. **Доменная дообучение.** Fine-tuning LLM и эмбеддинг-модели на туристических диалогах повысит качество как retrieval, так и генерации.
